# Artifact runtime

Derive uses `@aniraga/open-artifact-runtime/shared` for collection state.
The shared client owns optimistic values, reconciliation, subscriptions, and rollback.
It uses the same collection rules as the server.

The kit and Derive use `@aniraga/open-artifact-server/collections` for saved mutations.
The module reads, applies the mutation, and retries a lost compare-and-swap.
Native HTTP routes and kit tools now use the same state storage adapter.
It stamps each write with the authenticated actor. Malformed stored state refuses the write.
A database error remains a database error. It cannot become a seeded collection.
Derive adapts its existing metadata store. It keeps access checks, rate limits,
actor attribution, live broadcasts, and the activity ledger.
The module reports whether a result is saved. A changed result identifies its item.
The host sends side effects only after the write succeeds.

Derive publication uses `@aniraga/open-artifact-server/source`.
The shared kernel keeps original source bytes separate from rendered HTML.
The host adapter preserves Derive's IDs, bylines, access, formats, and storage quotas.
It uses the existing native atomic writes for creation, conditional saves, autosave replacement, and unconditional append.
The adapter reuses the prepared source blob. It refuses a different content hash before metadata changes.
The host keeps format classification, Skill relations, titles, and publish notifications.

The editor captures source operations through `@aniraga/open-artifact-runtime/source`.
The shared runtime omits generated page content and preserves the live caret during sync.
Source operation and sync response types come from the shared protocol.
Derive's frame adapter retains the existing messages and editor controls.

The kit and Derive use `prependArtifactHead` for runtime insertion.
The shared scanner skips comments, raw text, templates, and quoted attributes.
It preserves a leading charset declaration and inserts before authored CSP.

Element selectors and saved-version recovery use the shared protocol source entry.
Derive supplies stored versions, access checks, and comment state changes.
The shared scanner excludes inert markup and decodes attributes as the browser does.
Saved selectors and original snapshots retain their existing fields.
Element resize and style edits also use the shared source entry.
The editor changes actual style attributes. It preserves quoted examples and encoded CSS strings.

`shared-collection-client.ts` adapts Derive's existing messages to `StateBackend`.
It preserves `derive.shared`, `derive.increment`, the handle's return values,
caller slots, and the existing activity fields. It uses Derive's ownership fields.
Authored fields named `__actor` or `__slot` remain ordinary data.

The host keeps authentication and artifact access. It also checks browser activation
before each mutation. The opaque iframe receives no host cookies.
State replies belong to the requesting frame and its loaded document.
The host drops delayed replies after reload, replacement, navigation, or sign-in changes.
An expired request cannot open a sign-in prompt on another document.
Web module URLs include the existing build ID. Immutable caches cannot combine route
wrappers from one build with artifact modules from another build.

The adapter accepts responses only from its parent window. It validates snapshots
before it changes state. Older responses cannot replace a newer saved snapshot.
A failed mutation restores the last saved value before the caller receives the error.
A resync runs in the background.

`shared-state-client.ts` keeps Derive's content readiness and error reporting.
It uses the collection transport's host handshake. One message listener handles
the handshake, collection responses, and resync messages.

Run `pnpm build:shared-client` after changing the adapter or its runtime dependency.
The build creates `shared-collection-client.gen.ts`. Do not edit this file directly.
The existing client guard checks the generated bundle before delivery.

The collection client is one completed runtime seam. The full artifact kit,
anchor client, frame bridge, React reader, and format controls still need adoption.

HTTP and MCP comment creation use the shared thread module through `postArtifactComment`.
The host keeps access checks, rate limits, mentions, question options, and notifications.
Native IDs, original selector bytes, paths, body text, and attribution stay unchanged.
Mention metadata commits with the comment. Callers can name a new thread.
An existing root from another artifact cannot become a reply target.
The API maps the shared module's safe HTTP errors to its existing error response.

Exact source operation validation and application use the shared protocol.
Source maps, source stamps, incremental hashes, and page reconciliation use the same source owner.
Slide operations retain comment identities and rewrite copied DOM and structural references.
Layout edits read real attributes. Quoted attribute examples stay unchanged.

Structural editing and inverse receipts come from the shared protocol.
The shared inspector validates source ranges, region owners, and node identities.
Legacy deck backfill uses the same source rules for serving and saved edits.
Unsafe slides keep navigation identities without receiving structural handles.

Open-artifact owns video source classification and scene operations.
Timing edits change actual attributes. Scene copies receive fresh DOM and structural identities.
The shared runtime keeps inactive video scenes hidden when authored CSS sets their display.
Its visibility rule never enters stored source.
Playback, scene position, navigation, seek, and transitions use the shared video controller.
Derive keeps the authorized frame transport and the editor's history integration.
Video editing uses the stamped exact-source save path. Scene timing and captions
use shared attribute validation. Scene copies use shared identities and DOM references.
An autosave sync preserves the editor history. Playback styles stay outside stored source.
Unique scenes already saved as deleted still require recovery through History.
HTML-to-Markdown reading also uses the shared source entry.
Document outlines, source sections, landmark maps, and Markdown headings use this entry too.
Comments and inert markup cannot supply navigation identities. Section reads preserve exact source bytes.
Derive retains stored-format classification and its LaTeX renderer.
The shared scanner keeps quoted attribute examples inert and preserves literal HTML text.
The editor records explicit copy origins. Redo keeps working after an undo save removes a copy.
The original must remain in the current source. Other deleted blocks still require safe recovery through History.
