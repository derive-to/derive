AI-Era Guardrails

Encode the rules that keep an AI-heavy codebase consistent and safe as deterministic CI checks, so neither a person nor an agent can drift around them.

Thesis: an agent can ignore a CLAUDE.md instruction or a review comment, but it cannot ignore a red build. The design-token check (PR #62) proved the pattern on colors and sizes. This builds the rest of the layer: the semantic, cross-file rules Biome cannot express, plus the remaining footgun gaps the audit surfaced. Pure tooling and small refactors. No product behavior changes.

The four tiers

Each footgun is caught by the cheapest tier that can express it. Three exist already; the ast-grep layer is the new piece, matching how AI-heavy repos converge (Biome local, ast-grep / Semgrep semantic, scripts for repo policy, tests for behavior).

Execution · one PR per phase, gate green at each

P1

Safety guardrails

backend · highest value

The two footguns that are actual risk, not style. Build the ast-grep tier here.

  • Request validation. Add a zod ctx.body(schema) / ctx.query(schema) helper in api/src/lib/validate.ts; migrate the raw c.req.json() as {...} sites; ast-grep rule bans the raw cast outside the helper.
  • Authz coverage. A vitest test parses every routes/* module and asserts each POST/PUT/PATCH/DELETE handler references an authz helper (authorize / workspaceCan / collectionRole / ensureMembership). Stretch: a behavioral test hitting each mutation unauthenticated and asserting 403.
  • Wire ast-grep. Add sgconfig.yml + the rules dir; run sg scan inside pnpm run ci so it joins the existing gate.
P2

Backend consistency

backend

One error contract, one rate-limit story. Mostly mechanical migration behind a guard.

  • Standard errors. ctx.fail(c, code, msg) returning one shape; ast-grep bans bare c.json({ error }, code) in routes; migrate the call sites.
  • Rate-limit coverage. A composite limiter for the low-frequency mutations; a check requiring every mutating route to call limited() or carry an explicit "unbounded by design" comment.
P3

Frontend hygiene

frontend

Finish what the token check started: no arbitrary values, stable tests, no type escapes.

  • Spacing / z tokens. Extend check-design-tokens.mjs to flag arbitrary p-[..px] / w-[..] / z-[..], allowing calc() / var() / % / genuinely dynamic values.
  • Test-id coverage. Script: interactive elements in pages/ and components/shared/ must carry a data-testid; ui/ primitives exempt.
  • Type escapes. Flip Biome noNonNullAssertion to warn and fix the lone file; leave (e as Error) catch narrowing alone.
  • Storage keys. storage-keys.ts consts; ban raw string literals in localStorage.*.
P4

Wire + document

tooling · docs

Make the guardrails discoverable and the soft layer point at the hard layer.

  • CI. Confirm sg scan + every script run inside the single pnpm run ci gate (no separate, skippable step).
  • Catalog. A GUARDRAILS.md listing every rule, what it catches, and its escape hatch; referenced from CLAUDE.md so the agent layer points at the enforced layer.

Verification + non-goals

Gate, every phase

  • pnpm run ci green (biome + token + new scripts + ast-grep)
  • pnpm typecheck clean
  • pnpm test + test:pg pass
  • e2e green (smoke, artifact, review, login, chrome)
  • each new rule proven on a fixture: catches the bad case, passes the clean tree

Non-goals

  • No product behavior changes
  • No churn on the already-guarded set (DB-driver imports, SSRF, parity, test:pg)
  • Not banning (e as Error) catch narrowing (a TS limitation, not a footgun)
  • No Semgrep cloud / account dependency: ast-grep is a single MIT binary
  • Escape hatches stay (a tokens-ignore-style comment per rule) so legit cases are not blocked

Already guarded, for reference: DB-driver import bans, SSRF (isPublicHttpUrl), three-driver schema parity (Exact<>), test:pg full suite on real Postgres, no-console, no-floating-promises, centralized config, and the color + font-size token check.

Phase 2 · From guardrails to killer OSS

Phase 1 (P1–P4) shipped: 11 PRs, every footgun class enforced in one pnpm run ci gate. Phase 2 takes the rest of the project to the bar a top OSS clears. The repo stays private a while longer, then everything (CLI included) goes public — so each item is tagged now (private-compatible, set up immediately) or on public (prepared now, switched on at launch).

P5

Supply-chain + CI hardening

now · mostly Scorecard

The checks OpenSSF Scorecard grades. Cheap, high-signal, and they all run on a private repo.

  • Dependency automation. .github/dependabot.yml for the npm + github-actions ecosystems (grouped, weekly), plus a pnpm audit step that fails on a high/critical prod advisory. (now)
  • Secret scanning. gitleaks job in CI so a committed key fails the build. (now)
  • Pin the supply chain. SHA-pin every GitHub Action (not floating @v4); keep permissions: least-privilege. (now)
  • e2e in the gate. Wire the smoke suite into the PR trigger (it's built, just dispatch-only today); deep stays nightly. (now)
  • SAST + Scorecard. CodeQL (GHAS, free on public) + the OpenSSF Scorecard action + Best-Practices badge. (on public)
P6

Quality visibility

now

You can't improve what you can't see. Measure coverage and close the web-test hole.

  • Coverage + threshold. vitest --coverage (v8) with a realistic floor in CI, ratcheted up over time. (now)
  • Web unit tests. apps/web has only e2e today; seed vitest + React Testing Library for hooks, utils, and form/permission logic. (now)
  • Coverage badge. Codecov (free for OSS), posts coverage on every PR. (on public)
P7

Type + lint depth

now

Turn on the strictness a top TS project runs, behind the same green-gate discipline as Phase 1.

  • tsconfig strictness. Enable noUncheckedIndexedAccess, exactOptionalPropertyTypes, noImplicitOverride; fix the fallout per package. (now)
  • a11y to error. Promote the Biome a11y rules from warn to error (it's a publishing platform); fix the handful of violations. (now)
  • Import boundaries. dependency-cruiser: no cycles, no cross-feature reach, enforce the ports/adapters layering already in ARCHITECTURE.md. (now)
  • Bundle budget. size-limit on the web SPA + the API worker (Cloudflare limit) so a heavy dep fails the build. (now)
  • CI matrix. Test on Node 22 + 24, and add macOS for the native-module (better-sqlite3) path. (now)
P8

Distribution, prepared

build now · ship on public

The "CLI-first" promise needs the CLI installable. Wire it all up now; the publish step turns on at launch.

  • Release automation. changesets for versioned, changelog-driven releases across the workspace (replaces the static 0.1.0). (now: config; on public: publish)
  • Publishable CLI. @dock/cli gets description/keywords/files/author and a private:false-ready state, so npm i -g @dock/cli works at launch. (now: metadata)
  • Release workflow. A publish-on-tag workflow with npm provenance, gated so it only fires once public. (on public)
  • HTTP API surface. An OpenAPI spec for the Hono API (served + checked in) so clients/SDKs can be generated. (now)
P9

Discoverability + community

docs now · badges on public
